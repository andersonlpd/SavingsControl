Proposta de arquitetura · 8 de outubro de 2026

Controle financeiro e de investimentos

Uma aplicação web privada para uma pessoa: carteira buy-and-hold, controle de gastos, lançamentos retroativos e evolução patrimonial. Sem execução de ordens, recomendações de investimento ou chatbot.

Decisão resumida

Recomendada e escolhida

Monólito modular em uma VM

Django + SQLite em uma VM Linux, TOTP no login, assets locais Chart.js para gráficos e timer diário. A mesma aplicação entrega as páginas e calcula posições; backups ficam fora da VM.

Experiência

Web responsiva e eficiente

Dashboard próprio, tabelas e filtros claros, formulários rápidos e gráficos interativos. A qualidade visual não depende de usar React.

Limite importante

Estimativas transparentes

Preços e rendimentos calculados terão fonte e data visíveis. CDB/LCI/LCA estimados não equivalem a uma cotação de resgate da corretora.

Arquitetura e stack: alternativas avaliadas

Arquitetura A — escolhida

Uma VM Linux com monólito modular. Baixo número de serviços e custo; adequada a um usuário. A VM é ponto único de falha e o crescimento inicial é vertical.

Arquitetura B — não escolhida

Aplicação, banco e agendador gerenciados. Reduz manutenção do SO e tem teto maior para disponibilidade/escala, mas adiciona serviços, configuração e custo sem benefício atual.

Stack 1 — escolhida

Python + Django + SQLite. Páginas server-rendered, CSS responsivo próprio, JavaScript pontual e Chart.js empacotado localmente. Menos cola para formulários e cálculos no mesmo processo.

Stack 2 — não escolhida

TypeScript + Next.js + React. Boa para SPA muito interativa e compartilha linguagem no browser/servidor; exige mais componentes para TOTP, tarefas de fundo e precisão monetária.

Ambas as stacks têm ecossistemas web maduros e atenderiam a carga de uma pessoa; não foi presumido benchmark. Não há contratação planejada nem pesquisa local de disponibilidade.

Limites e validações antes de confiar nos números

Os valores são para acompanhamento, não para execução de ordens, declaração fiscal ou recomendação financeira. Renda fixa e impostos serão estimativas; mostrar fonte, data e hipótese de resgate.
  • Pluggy: o uso gratuito é pessoal e tem limite de conexões. Confirmar no consentimento se os cartões Bradesco retornam transações; a cobertura institucional não garante todos os produtos.
  • Ágora: consta na cobertura Open Finance de investimentos da Pluggy; validar posições reais no fluxo de conexão. A integração será somente para conferência, sem importar ordens para o ledger.
  • Vest: não foi encontrada nas listas públicas consultadas da Pluggy; manter registro manual.
  • Dados públicos de ações/FIIs/REITs podem ter limite de chamadas, atraso e lacunas de ticker. Guardar cotações usadas e permitir valor manual com data.
  • O histórico do patrimônio total vem de snapshots mensais digitados a partir da planilha; não se reconstruirá desempenho antigo por ativo.

Fontes de referência

  • Pluggy — transações com paginação por cursor.

  • Tesouro Transparente — taxas e preços diários; Receita Federal — tributação de 2026; IOF — texto vigente.

  • Estimativa pública de VM Azure (referência não vinculante); calculadora oficial Azure.
